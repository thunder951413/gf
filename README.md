## 启动

需要 Node.js 22.13 或更新版本，当前开发与验收环境为 Node.js 26。无第三方运行时依赖，不需要 npm install。

这台 Mac 已配置登录自启，日常直接打开 <http://127.0.0.1:8765/>。查看或移除自启：

```sh
npm run service:status
npm run service:remove
```

移除自启只停止服务，保留数据。重新安装：`npm run service:install`。该命令创建当前用户的 `~/Library/LaunchAgents/local.youjian.companion.plist`，无需管理员权限；后台日志保存在 `.runtime/`。移动项目目录或更换 Node 路径后，应重新安装服务。

不使用自启时，在本目录双击 `启动有间.command`，或运行：

```sh
npm start
```

打开 <http://127.0.0.1:8765>。终端按 Ctrl+C 停止。需要其他端口时运行：

```sh
npm start -- --port 8766
```

服务只监听本机，不开放局域网或公网。后台运行时关闭网页不影响采集和联系；电脑休眠、关机或退出登录时暂停，恢复后继续，不集中补发错过的主动话题。跨设备访问和鉴权属于后续部署阶段。

## 她如何主动联系你

默认开启，可在“主动陪伴”里修改节奏、兴趣方向和桌面提示：

- 每约两小时自动收集一次 RSS/Atom，时间有少量随机浮动。默认来源为少数派、Solidot、BBC 中文、ScienceDaily 和机核，覆盖科技、时事、科学知识及游戏文化。
- 09:00–23:00 内随机安排联系，默认两次之间通常相隔 90–180 分钟，每天最多四次，包含你约定的提醒。当前仅林晓薇会主动联系。
- 从摘要较完整、时间合适、未重复分享的内容中选择；也会延续当前角色与你的共同话题，或由林晓薇分享当前生活事件。模型认为没有值得聊的内容时可以不发。
- 正在聊天或输入、开启“暂时安静”、林晓薇在 24 小时内有两条主动消息未回应时暂缓。最短/最长间隔是计划联系时间，遇到这些条件或没有合适内容时会顺延。重新启动不会重新抽掉已保存的计划，也不会补发一串错过的消息。
- 新消息进入对应角色会话，带来源、联系理由与“这个话题不错 / 少聊这类 / 稍后再聊”反馈。“少聊这类”目前降低相同来源的后续权重，尚非语义兴趣学习。

不需要手动点“现在找我聊一次”；该按钮只是即时体验入口。模型未配置时仍自动采集，主动联系会等待可用模型；你明确选择剧情选项时可以继续阅读已有作者内容。保存有效模型配置后，会在约一分钟后按当前时段和免打扰规则尝试第一次开场；后续模型错误会退避重试。

开启桌面提醒时，macOS 后台服务会请求一条通用通知，不显示私密对话；实际显示由系统通知权限和专注模式决定。浏览器提醒仅在你点击授权后启用，不能代替页面关闭后的桌面通知。新消息不会自动播放语音。

自动选题会使用你配置的模型，可能产生费用；每天最多尝试 `联系次数上限 × 3` 次（默认 12 次，含失败或跳过），每次最多请求 1800 个输出 token，开场正文另限1200字符。普通手动聊天不计入这一尝试上限。使用官方 DeepSeek v4 接口时，短开场和连通性测试显式使用[非思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)，避免有限预算只产生思考而没有正文；林晓薇普通聊天会在同一次调用中返回正文和简短情绪线索，官方 DeepSeek v4 使用非思考 JSON 模式、最多3000输出token；闻溪和阮绵普通聊天最多2000输出token，官方DeepSeek v4同样使用非思考模式；其他兼容服务不发送这些专有参数。

## 开始使用

1. 打开“设置”，填写已有服务的接口根地址（通常包含 `/v1`）、模型名和 API 密钥。本地无密钥服务可留空。使用的是 Chat Completions 兼容格式，根地址应不带查询参数或片段。
2. 保存后点击“测试已保存的配置”。测试只发送一句简短问候，不发送记忆和聊天记录。
3. 选择林晓薇、闻溪或阮绵开始聊天。自由聊天需要模型；明确的情境选项由作者文本直接推进。调用失败会显示真实状态并保留待回复输入。
4. “记得的事”可以明确添加、修改、删除记忆，并指定三人共享或只给某一角色。另外会按角色自动整理累计会话回忆，保留近期原文；可以校正或清空摘要。

林晓薇的长期整理由程序调用设置中保存的模型完成，保留有原文证据的按日核心记录；在“设置 → 相处的节奏 → 按日整理历史”配置时间、立即整理，或查看整理结果和原文依据。

林晓薇的日常聊天默认使用 **当日原文＋按日核心记录**：当日按北京时间00:00划分，原文窗口不再滚动保留24小时。每天默认 **02:00** 整理今天以前的内容，可在02:00–11:59内调整早晨时间。程序未运行时不会在凌晨前提前补整理；02:00后首次交互若仍有待整理内容，会先调用配置模型提取、核对，通过后才生成角色回复。排队输入在页面显示整理进度，失败时保留输入供重试或取消。

程序去掉重复语气和修饰，保留事情、观点、双方归属、日期、数量、条件、约定和进度，再调用模型对照原文核对。原文仍受60000历史 token 保守预算约束；预算计入时间标记和引用包装，不包含人设、资料、长期记忆或输出，真实 token 以服务商用量为准。00:00–02:00尚未整理的昨天内容可按需recall原文。关闭按日整理后可恢复1–30天的原话窗口。

已整理的旧原文不会重复注入每轮；近期核心及相关旧事项在预算内补充，精确措辞和未列细节按需查原文。尚未到整理时间、核对未通过或模型不可用时，较早原文在原有七天与预算范围内暂时补充，避免记忆断档。整理不删除聊天记录；编辑、屏蔽或删除原文会使相关批次失效并等待重建，用户手动记忆保留。机制、实测与限制见 [对话历史窗口](HISTORY-WINDOW.md)。

普通聊天的自然性检查区分用户正在交流、明确告别、主动求建议和需要安慰：避免无端以叮嘱开头、以“你忙你的”推开交流或以“你舒服就好”惯例收尾。检查使用本地规则，复用原有最多一次模型修复，最后只清理明确违规的语句，不补固定话术。规则能检查特定问题，不能保证每句都自然；可用 `node scripts/evaluate-conversation-quality.mjs --live --label review` 在隔离的聊天快照中复测，报告在被 Git 忽略的 `.runtime/conversation-quality/`，不会向微信发送测试消息。
5. “一起看看”可以管理 RSS/Atom 来源、立即收集新内容、打开原文和把指定文章带入与闻溪的讨论。后台也会自动收集与选题，标明仅有摘要或已备读正文片段，相似条目归组；这不代表独立事实核验。
6. “情境故事”提供《雨夜拾光》《纸月亮工作室》《镜潮之城》，每篇独立存档；按钮或明确的自然语言选择会推进，暂停和切换保留进度。“雾港来信”作为旧的独立双人剧本保留。
7. “留到以后聊”可以明确约定角色、话题和时间。后台每十秒检查一次，与主动陪伴共用每日总量；暂时安静时延后。

## 连续交流、后续事项与收藏

- 网页发送消息后留约1.2秒接收连续补充；模型开始后再补发，会取消旧草稿，以这一轮全部输入重新生成。自然节奏首条目标仍为4–9秒（包含生成时间）；较长回复最多拆成4段，每段约1.2–2.8秒间隔；不为每个气泡另调模型。即时模式直接显示完整回复。
- 已经看见的回复才写入历史与摘要。未送达的后续段落遇到新输入会取消，服务重启不会突发连发。待回复输入保存在SQLite，关闭页面不丢失；失败显示“重试/取消”。“撤回待回复消息”会撤销本轮尚未写入正式聊天的输入。
- 取消请求不保证供应商免计费；用量页分别显示失败与已停止，没收到token用量记为未知。
- “留到以后聊 → 她惦记的后续”查看自动记下的安排，可改回访时间、标记结束或不用再问。只从新的明确私聊识别面试、考试、演示、体检等近期事项，不回扫旧聊天，不为提取另调模型。常见日期包括明天、后天、今晚、下周某天；不确定表述跳过。一般等事情过后再轻问一次，72小时过期，沿用主动陪伴所有限额。情境小说里的行动不进入现实事项表。
- “一起看看 → 关注后续”最多跟踪20个具体话题。从已有采集结果里匹配标题主题词，排除同网址和旧分享，交给闻溪连同原始资料筛选；不把关键词相关冒充已核验的新进展，也不另加全网搜寻请求。
- 聊天的“收藏片段”进入“生活足迹”，最多100条，可添一张本地配图和备注，再回去聊。图片居中裁为512像素正方形，标注为你添加的配图，不发送到对话模型。取消收藏不会删原聊天。生活近况页同时展示林晓薇已经主动发出的生活分享。

“设置 → 知乎资料研究”中填写知乎开放平台的 **Access Secret**，保存后可用“测试额度”验证；这里需要开发者凭据，不使用网页登录 Cookie。接口和账号权限见 [知乎官方文档](https://developer.zhihu.com/docs)。对话模型仍在上面的独立设置中配置。

后台约每两小时独立运行：新浪公开热榜、48 小时内的订阅新闻、知乎热榜及官方全网搜索发现话题 → 按兴趣加权抽样并去重 → 官方站内检索可引用的知乎回答/文章 → 直答 Agent 整理背景、观点差异与讨论问题 → 加入“一起看看”和角色主动选题库。普通聊天不必等待研究结束。关闭“主动陪伴”会同时暂停自动研究；安静模式只暂停主动联系。

默认每轮最多研究 2 个话题，每个本地自然日最多 20 次业务请求，其中直答最多 4 次。这是本应用的调用次数上限，不等于官方剩余额度或固定费用；失败也计数，重启不清零。官方额度查询独立限频为每分钟一次。达到直答上限时可以保留明确标记的真实回答摘录；没有可引用回答时跳过。鉴权失败、限频会退避，手动“立即研究”不会绕过预算或冷却。

资料卡区分“AI 整理”和“知乎回答摘录”，展开可核对话题出处、作者、链接和摘录；主动开场也保留这些来源。检索得到的观点和 AI 整理都未经独立事实核验。研究只发送公开话题和公开摘录，不发送角色私聊或个人记忆；这些资料进入陪伴对话后，仍按普通对话的模型上下文规则使用。

没有 Access Secret 时仍可发现新浪公开话题和近期订阅内容，界面显示等待配置；不会进行知乎鉴权调用。新浪入口是[公开热榜页面](https://sinanews.sina.cn/h5/top_news_list.d.html)的嵌入数据，不是微博官方 API，页面结构变化时会报错并保留已有资料。完整接口、存储和调度说明见 [ZHIHU.md](ZHIHU.md)。

## 角色与对话

当前只保留林晓薇作为可聊天和主动联系的角色：

| 角色 | 她更在意什么 | 她如何起头 |
| --- | --- | --- |
| 林晓薇 · 日常恋爱陪伴 | 你的近况、自己的生活、低频暧昧与彼此需要 | 围绕苏州生活、当前经历和回忆自然分享 |

林晓薇围绕生活事件、内在状态、资料和到期的回访展开。其他角色的配置及运行数据已移除；`output/backups/` 中的本地数据库备份也只保留林晓薇的数据。

林晓薇的基本行程由程序维护，模型根据固定档案、事件、资料、历史回忆和当前聊天表达。阶段变化不再中断回复，不必等到达才聊地方文化。旅游期间不会抽取相冲突的居家事件；错过的阶段不集中补发。旧聊天原文保留，但旧弥月的同学/修书师身份不再用作日常对话历史。详细的概率、持续时间和升级处理见 [人物机制](CHARACTERS.md)。

旧剧本入口和接口已关闭。模型表达与回忆整理仍可能出错，可以在“记得的事”校正。

## 语音

应用复用 `http://127.0.0.1:7866` 上的现有 TTS 服务。点击助手消息下的“朗读”，应用会创建音频任务并在浏览器播放，支持暂停、继续、停止，也可边听边输入。设置 → 本地语音可为林晓薇选音色、保存、试听，也可选择跟随全局设置。当前按句分段生成并连续播放，先播放已完成的第一段，后续两段以内预备；停止会取消整个语音会话。试听仍为单段音频。尚非逐 token 的语音流式通话。

点击“说话”可以录音转文字，检查后再手动发送。需要浏览器麦克风授权，以及现有本地语音识别服务处于运行状态。本应用不自动启动、停止或重配现有 TTS/STT 服务，也不在后台持续监听麦克风。

音色目录由 `GET /api/voices` 读取。独立音色调用使用 `POST /api/generate-stream/start`，传 `use_service_settings=0`、`voice_name`、`example_audio_path`，保留当前模型与合成参数，ICL参考文本随所选声音更换；缺少文本时使用xvec。不会修改TTS全局预设，音频路径仅由后端从本地目录选取。

TTS 密码读取环境变量 `QWEN_TTS_ACCESS_PASSWORD`，或本机已有的 `/Users/surfing/tools/tts_generator_moss/.env.macos` 中同名设置；不会返回给前端。

## 配置和数据

`data/life.sqlite` 保存会话、记忆、内容、提醒、故事、主动计划、反馈和已读位置；`data/provider.json` 和 `data/zhihu.json` 保存页面中填写的模型、知乎配置，权限为 0600，数据目录为 0700。数据仅在本机保存，不等于加密存储。

可复制 `.env.example` 为 `.env.local`，仅支持简单的 `KEY=VALUE`，不会作为 shell 执行。使用 `npm start` 时读取，已有环境变量优先。支持：

- `LIFE_MODEL_BASE_URL`、`LIFE_MODEL_NAME`、`LIFE_MODEL_API_KEY`：覆盖页面保存的相应模型配置。
- `LIFE_TTS_BASE_URL`：语音服务地址。
- `LIFE_LISTEN_HOST`、`LIFE_ALLOWED_HOSTS`：默认仅本机访问。内网 / WireGuard 使用时，可在 `.env.local` 设置 `LIFE_LISTEN_HOST=0.0.0.0` 和 `LIFE_ALLOWED_HOSTS=192.168.1.145`，执行 `./ctl restart` 后访问 `http://192.168.1.145:8765/`。访问地址按实际内网 IP 填写，手机的 WireGuard 路由需要能到该地址；本机桌面端仍用 `127.0.0.1`。这采用现有私有网络访问方式，不提供公网账户登录。
- `QWEN_TTS_ACCESS_PASSWORD`：语音服务密码。
- `LIFE_FEED_PROXY`：公共订阅/新浪采集和知乎请求默认使用的受信任本地 HTTP 代理。
- `LIFE_ZHIHU_ACCESS_SECRET`：覆盖页面保存的知乎凭据。
- `LIFE_ZHIHU_PROXY`：单独指定知乎请求使用的本地 HTTP 代理，未设置时沿用 `LIFE_FEED_PROXY`。

当前 `.env.local` 已按本机启用的系统代理设置 `LIFE_FEED_PROXY=http://127.0.0.1:7897`。如果代理端口变化，请修改该值；不需要代理时删除该行。

采集器默认拒绝私网和本机地址，并验证每次重定向。显式配置代理后，对公共域名支持代理软件的 `198.18.0.0/15` fake-IP 解析；其他私网目标仍被拒绝。代理因此属于你的受信任网络基础设施，HTTPS 仍校验目标证书。不会下载来源中的音视频文件。

使用远程模型时，本次回复所需的当前角色聊天、允许的记忆、故事和引用内容会发送给所配置的模型服务。其他角色私聊不会一起发送。最近对话和记忆按上下文预算读取；后台自动维护累计摘要，尚未加入向量语义检索。

删除长期记忆会立即从后续的记忆检索中移除，但历史聊天中已经说过的内容仍然保留。首版没有自动备份、聊天删除界面或跨设备同步。需要手动备份时，先停止应用再复制整个 `data/` 目录。

## 当前边界

- 已实现可配置模型的真实调用路径；实际模型的中文表达、亲密交流能力和响应时间，需要填写你的接口后试用评估。

## 头像与回复节奏（0.7.1）

在“设置 → 相处的节奏”切换自然或即时回复。默认自然节奏从发送开始随机等待约4–9秒，包含模型生成时间；生成本身更慢时不叠加等待，不增加模型请求或token。等待期间同一角色保持忙碌，回复尚未入库，刷新轮询不会提前显示正文。

“设置 → 角色头像”可分别上传JPG、PNG或WebP图片，最多8MB，浏览器居中裁切为512像素正方形后预览，点击保存才应用。头像保存在本地SQLite，与角色列表、欢迎页和聊天消息同步；可恢复默认。头像不进入模型上下文。人物资料里也有“设置头像”入口。

## 页面背景（0.7.2）

“设置 → 页面背景”可上传JPG、PNG或WebP，支持铺满、完整显示、拉伸、平铺，以及顶部/居中/底部位置、0–90%浅色遮罩和0–12像素模糊。修改先在当前页面预览，保存后本机其他会话页面与刷新都会使用同一背景；取消预览恢复上次保存值，恢复默认清除背景。

图片最多12MB，浏览器保持比例缩小到最长边1920像素、压为JPEG再保存，本地后端限制解码后2MiB。背景独立存储，不送入对话模型、不随每次聊天读取，不额外消耗token。文本气泡与控制面板保留底色，移动端布局也适配。当前为全应用背景；角色独立主题属于后续方向。

## 林晓薇的微信通道

打开 `/weixin.html`（主页面设置中也有入口），点击“开始手机配对”，用微信扫码确认。手机上可先保存二维码，再在微信扫一扫中选择相册。确认后先给她发一句文字，建立微信允许回复的会话上下文。绑定只接受该微信用户，只接入林晓薇；其他角色不会转发。

服务通过腾讯公开的 iLink 协议长轮询收取消息，无需公网回调或在手机上维持到本机的 VPN；Mac 服务需要持续运行并可访问微信接口。设置页面仍需通过本机地址或内网访问。TTS 仍是独立服务，这一版微信收发文字，不传语音或图片。

微信消息进入现有 `ChatQueue`，复用同一模型、角色状态、历史与记忆，不额外启动模型代理。网页或桌面发起的对话只在有间回复；微信发起的对话通过微信回复，同一轮连续回复尽量合并。桌面端始终显示两端的完整聊天记录。连续输入合并时，以最后一条输入的渠道作为回复渠道，分段回复和重试保留该渠道；绑定之前和暂停期间的旧聊天不会集中补发。主动消息沿用现有生活事件、免打扰和主动交流设置，仅在最近一次输入来自微信时向微信发送，并可在微信页面单独关闭。

`lib/weixin-client.mjs` 隔离协议、超时和错误；`lib/weixin-bridge.mjs` 维护入站去重、游标、发送队列和绑定会话。入站游标与收件记录在同一事务保存；发件记录持久化。明确被限流拒绝时最多尝试三次，网络超时等无法确认是否送达时保留为“结果不确定”，不会盲目重发。微信拒绝过期会话时等待你发来新消息；普通回复超过24小时、主动消息超过6小时不再补发。微信的可发送条数及会话有效期由平台决定，不能保证一直主动推送。

登录凭据只保存在被 Git 忽略的本地数据库，状态 API 不返回令牌。二维码在本机通过 `qrencode` 转为 PNG，不请求二维码内容中的链接；macOS 可用 `brew install qrencode` 安装。断开连接删除绑定凭据并取消待发消息，不删除已有聊天。投递状态中的“微信已受理”仅指接口返回成功，不代表手机已经收到或用户已读。

协议依据：[腾讯插件源码](https://github.com/Tencent/openclaw-weixin)、[消息发送结构](https://github.com/Tencent/openclaw-weixin/blob/main/src/messaging/send.ts)。本程序直接实现消息适配层，不依赖安装 OpenClaw。
