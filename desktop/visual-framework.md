# 林雨薇视觉资产框架

`assets/visual-catalog.json` 是唯一的视觉目录。它列出身份、发型、表情、色板、穿搭、场景和姿势，`assets` 只记录实际存在的完整照片并使用稳定 `id`。实体的 `ready` 表示可供选择；人物只有同时为 `approved`、带安全相对路径和尺寸的 asset 才能渲染。`planned` 是待补齐的目录状态，不是假定可显示的组合。

## 完整造型，而非素材拼装

一条 asset 同时固定身份、发型、服装、姿态、表情和色板。解析和界面优先返回精确已验收文件；当某个维度没有精确文件时，返回结果必须标明实际渲染的完整造型，或报告没有可用照片。不得把已有长发站立照标为短发、挥手或另一种表情，也不得把目录维度当成可任意相乘的笛卡尔积。

为保证自动状态回到 idle 时发型不改变，每个可自动切换的发型应有对应的已验收 idle 完整造型。自动、锁定、生活状态、最短停留时间和设置持久化由 `lib/appearance.mjs` 的最终后端逻辑决定；客户端不应另行猜测或复制时序。服务端只会从现有 approved 文件中选取，并会校验场景与服装兼容性。

## 调色、光线与场景

本地换色本身也是已验收的完整 PNG。当前只验收了**裙子或短裤**遮罩的换色；遮罩必须只覆盖目标衣物，避开脸、皮肤、头发和原始 alpha 边缘。不要把未遮罩的服装、人体或头发写成可换色。

人物照片的光线、阴影和反射都已烘焙进原图。场景卡片只在透明人物后方合成背景，并可在定义的区域显示雨或雪；它会增加柔和的近似接触阴影，但不会按光源重新渲染人物或计算真实投影，也不提供全 3D 骨骼、眨眼或口型动画。

场景的 `compatibleOutfitIds` 是唯一的服装兼容规则。`access: "private"` 的衣着只允许写入 `privacy: "private"` 场景；当前的私密内搭是暗玫瑰色不透明吊带、居家短裤和同色罩衫，不是胸罩。场景、背景、原图和换色数量都从 catalog 动态读取，维护文档和验证器不应把当前数量写死。

## 验收和交付

每个 approved 人物图、ready 场景背景和引用的 recolor mask 都必须使用安全的相对路径、实际存在的 PNG，并满足 1024×1536。人物 cutout 必须是透明 PNG（IHDR color type 4 或 6）。每个 ready 发型、表情、色板、服装、姿势和场景至少需要一个实际可读取的 approved 人物资产；ready 场景还需要背景文件。

运行以下命令进行文件和目录验证：

```sh
node scripts/verify-visual-assets.mjs
```

输出是简明 JSON，包含动态统计和所有发现的缺失或契约问题；脚本只读取本地目录和 PNG 头，不调用模型。通过它不等于桌面 UI 已完成生产环境验证。

外部 3D rig 可以在许可允许时保留为独立备用渲染路径，不能替代目录中已验收的写实身份。新照片、背景和遮罩应记录来源、使用许可、可分发范围和撤销条件。
