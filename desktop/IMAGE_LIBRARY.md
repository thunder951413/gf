# 林晓薇图片素材库 · 0.5.1

入口：网页设置中的“图片素材库”，或者桌面菜单“图片素材库 · 批量上传与分类”。地址 `/image-library.html`。

## 使用

1. 一次选择多张 PNG / JPEG / WebP（单张最多 12 MB、单边最多 12000 像素、总计最多 4000 万像素）。逐张上传并报告失败，可以单独重试；相同内容自动合并，不覆盖已有标注。
2. 新图进入待分类。点开图片，可以修改名称、多个适用场景、活动描述，以及服装、发型、表情、季节、姿态等自由标签。每项最多 24 个标签，单标签最多 64 字；活动和名称最多 120 字。
3. 场景沿用现有六个桌面场景。同一场景可有多张候选图，一张图也可属于多个场景；服装、表情和活动用标签进一步细分。
4. 需要去背景的图可标记待处理。处理好的透明 PNG 通过“上传透明版本”挂在原图下；原图保留，两种版本可切换预览和下载。当前支持含真实透明像素、非交错、8 位 RGBA / 灰度加透明通道的 PNG；不把画上去的棋盘格当作透明背景。
5. 明确点击“将预览版本应用到桌面”才切换场景。默认保持比例完整显示，可选铺满裁切。旧原生单图上传接口保持兼容，已有场景图片自动收入素材库。

批量导入、分类和场景切换均在本地完成，不调用对话或视觉模型，不消耗模型 token。没有自动识图或一键抠图后台。后续通过 Codex 看实际图片填写分类，并按具体图片处理背景；不根据文件名猜场景、不凭标签写入角色的真实经历。

## 分类和去背景的处理原则

- 先确定用途：生活场景照片保留环境；独立桌面角色才需要透明背景。
- 场景、活动、外观标签分别保存。例如：书房＋冬日居所 / 沙发读书 / 长发、针织衫、坐姿、微笑。
- 人物与家具发生接触时，评估人物连同沙发/椅子一起保留，避免抠完悬空。
- 背景编辑只另存派生图。逐张检查脸和体态有没有被改动、发丝和衣服边缘、手指和书本、脚与地面的接触，再决定是否使用。
- 素材类别与角色当前生活状态分离。上传一张旅行照不代表她刚刚去旅行；不会为了匹配照片编造聊天历史。
- 当前手动应用，不在每条聊天后随机换图。未来接入生活状态时，应从已标注候选中选择并保持场景持续性。

## 接口

`GET /api/image-library` → `{revision, items, scenes}`。items 包含 id、name、sceneIds、tags、kind、activity、background、originalUrl、cutoutUrl、createdAt、updatedAt。

- `POST /api/image-library/upload`：`{image, name?, sceneIds?, tags?, kind?, activity?, background?}`；image 是 data URL。kind 为 scene / portrait，background 为 keep / transparent / needs-removal。
- `POST /api/image-library/metadata`：`{id, name?, sceneIds?, tags?, kind?, activity?, background?}`。
- `POST /api/image-library/derivative`：`{id, image}`，透明 PNG data URL。替换透明候选，不替换原图。
- `POST /api/image-library/apply`：`{id, sceneId, variant: "original" | "cutout", fit?: "contain" | "cover"}`；明确激活目标场景。
- `GET /api/image-library/files/<sha256>.<png|jpg|webp>`：仅访问库中已登记的文件，返回正确 MIME、nosniff 和不可变缓存。

原图及透明版本在 `data/scene-images` 按内容哈希保存；元数据在 SQLite metadata 的 `image-library:v1`。接口不接受任意文件路径或外部图片 URL。读取列表仅补录新出现的旧场景图片，不恢复用户主动清除的分类，不将透明版本再次当成原图导入。
