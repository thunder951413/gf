# 桌面双击关怀验收 · 2026-09-10

桌面 0.5.4（11）将双击视为明确的陪伴邀请。一分钟内再次双击升级为亲亲、抱抱和关心；生成期间多次追加会合并成一次亲昵回应。单击延迟至系统双击判定结束后打开聊天，拖动和右键取消待处理单击。

请求沿用林雨薇的聊天背景、记忆和回复检查。双击仅作为内部交流意图，聊天记录只保存她的回复，不保存操作描述或伪造用户原话；操作信息留在独立的幂等回执中。她自然地以惦记、想念开口，操作用语泄露会进入一次修复检查。它不受定时主动聊天、主动消息时段或次数上限限制，不修改这些设置，也不重新启用预置阅读。输入正常聊天会取消正在生成的桌面关怀，优先接文字消息。

`POST /api/desktop/attention` 接受 `requestId` 与 `level: care|affection`。请求标识与聊天回复在同一事务内保存，重试及服务重启不重复生成已成功的回应。失败不记成功收据。桌面仅重试忙碌状态和少数临时连接错误；取消会清掉待发送的亲昵请求。立即返回的回复与轮询去重，旧轮询不会让它再次计数。等待提示保持可见，追加生成不覆盖已收到的第一句。

验证：

- `npm test`：636 项通过，含 6 项桌面关怀 API 回归。
- `npm run check`、`npm run desktop:test`：通过。
- `node desktop/attention-test.mjs`：临时 AppKit 程序调用三个真实视图的点击处理器，并连接隔离 HTTP 服务；验证单双击、第二次追加、忙碌重试的相同标识、实际气泡正文、取消清队列、消息计数。
- 用正式数据的临时副本和当前模型进行两次试聊，care 与 affection 均返回 200；第二次沿用第一句上下文并表达拥抱、亲吻和关心。正式聊天历史没有写入测试消息。
- 构建 0.5.4（11），部署前保存 SQLite 快照；部署后验证签名、实际运行版本和已有消息一致性。

交互时限：再次双击的升级窗口为 60 秒；等待忙碌或连接恢复最多约 125 秒。永久错误会显示可重试提示。响应内容由模型结合当时对话生成，具体措辞不会固定为测试样例。
