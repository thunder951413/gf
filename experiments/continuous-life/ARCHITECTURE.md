# 林雨薇持续生活：实现与验收

本次把服务端的持续生活状态作为聊天和桌面共同读取的事实来源。日程推进不调用模型；模型负责把当前生活、历史和关系自然表达出来。

## 一条交互路径

1. 服务启动立即推进一次，之后每 30 秒检查北京时间、旅行阶段、约定、人物属性与身心状态。
2. 每个自然日只随机生成一次日程并存入 SQLite。工作日与周末不同；早餐略有浮动，下班可去咖啡馆、小酒馆或回家，晚上可读书、听音乐或画画。属性影响概率。旅行沿用原有每周默认 5% 机制及固定起止时间。
3. 已到点的个人安排优先于普通作息；旅行改变地点，但吃饭、休息、睡觉依然持续。共同约定等待用户确认，不自动宣称双方已经参加。计时结束只结束时段，不能代表读完作品。
4. 有些转变产生带到期时间的交流机会。事件唤醒主动联系调度，但仍经过安静模式、允许时段、最短间隔、每日次数、未回复次数和正在输入检查。活动转变不等于必须发消息。
5. 用户回复与主动联系都调用同一个 `prepare`，获得同一份当前状态和日程。用户触发另附用户消息；主动触发另附本次机会及材料。
6. 回复投递前检查状态版本。如果用户回复生成期间场景跨界，丢弃旧稿并按新状态重试一次。主动消息失效则不投递。只有成功保存的消息才确认机会已使用。
7. 桌面根据同一当前活动，匹配素材库已有的场景、活动和标签；一次活动内固定图片。有透明人物版本可优先用该版本。没有适合图片时保留当前图片。手动应用图片自动固定，直到重新开启自动匹配。

状态存于 `companion_runtime:miyue`。日程、活动、机会和投递回执能跨重启恢复；长时间离线直接追到现在，不补发过期日程。好感不会随运行时长自动增长，关系事实仍由真实对话、确认和已有关系记录积累。旧随机生活片段不能覆盖当前活动，也不会作为一个正在别处发生的事件强塞到提示词里。

## 页面和接口

设置入口「持续生活 · 状态与安排」以及桌面同名菜单打开 `/runtime.html`。可查看当前地点、活动、感受、亲近愿望、开始结束时间、下一项、当天安排、近期变化和服务运行状态；创建指定日期的个人或共同活动，修改标题、时间、地点、时长，并开始、暂停、继续、确认完成或取消。

- `GET /api/companion-runtime`：当前快照、服务状态及图片选择结果。
- `POST /api/companion-runtime/settings`：携带 `revision` 更新生活联动和自动图片设置；冲突返回 409。
- 约定继续使用 `/api/companionship/agenda`，所有修改共用同一约定仓库。
- 原有身心参数、亲近需求和性格编辑功能保留；修改会进入下一次准备。

关闭生活联动只关闭该通道产生的机会与图片联动，状态仍推进；原有主动陪伴总开关仍控制所有主动消息。图片固定不停止生活，也不停止联系。

## 上下文与费用

固定人物与输出协议 → 固定明确记忆 → 历史摘要 → 原始近期聊天 → 本轮变化的状态/资料/行为 → 触发说明与用户消息 → 请求当前日期时间。

主动与用户触发的固定前缀相同。当前用户消息不放进历史裁剪预算。林雨薇保留最多 32 条、18,000 字符近期历史，以及最多 12 条、5,000 字符明确记忆；近期事件简记有单独 850 字符预算。每次状态维护不消耗模型 token。普通回复输出上限 4,096 token，高话量上限 6,000 token；正文最多 6,000 字符，实际仍随话题和话量设置变化，并不要求每次写长。

这个布局提高相同前缀复用机会，不能保证每次缓存命中。历史摘要更新、记忆变更、滚动历史及供应商缓存保留时间都会影响命中。实际缓存 token 继续通过已有用量页面展示。机制依据：[OpenAI Prompt Caching](https://developers.openai.com/api/docs/guides/prompt-caching)、[DeepSeek Context Caching](https://api-docs.deepseek.com/guides/kv_cache/)。

## 验收材料

- `simulate.mjs`：真实仓库、隔离数据、固定种子，14 天，每 5 分钟一次检查。报告 `report.md` 和 `simulation-results.json`。
- `live-model.mjs --live`：使用已配置模型，但创建隔离数据库，完成工作、承接话题、咖啡馆、亲近、展开讨论、夜间以及主动分享。逐轮原话和接口用量存于 `live-results.json`。脚本自动移除临时凭据。
- 单元/集成测试覆盖跨午夜、旅行期间吃饭睡眠、约定冲突/取消、离线/重启、不重复投递、安静与限频、场景固定、状态过期重试、长回复及跨触发缓存前缀。

程序可以保证时序、唯一状态、记忆预算、投递去重及规则检查。自然措辞、观察细节和内容趣味仍受模型影响；特定模式检查能拦截已知问题，不能证明任何模型都永不出戏。测试报告保留真实原话，便于继续按体验改进。
