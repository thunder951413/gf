# Retrieval diagnosis after the frozen run

This review uses only `offline-results.json`, `results.json`, the frozen fixtures, and the frozen retriever. It does not rerun or tune against the held-out probes.

## Observed result

The held-out set reports an any-expected hit on 11 of 16 probes and all expected items on 10 of 16. Two probes intentionally expect an empty result and both stayed empty. Among the 14 positive-recall probes, 9 found at least one expected item and 8 found all expected items. The five complete misses are therefore material; they are not all unavoidable consequences of lexical retrieval.

The continuous attention arm exposes the same problems more strongly. `switch-book`, `recall-drink`, `updated-drink`, `travel-food`, and `latest-preference` all have `rankedCount: 0`, despite containing literal terms present in a memory or its keywords. These are implementation failures. Other misses, such as mapping “身体悬着、没什么重量” to the ocean record and “卡片送出去” to an unmailed postcard, need synonym or semantic knowledge that the current experiment explicitly lacks.

The partial probe `那个客户有没有把要求说清楚` returns `design` but not `design-detail`. Both records belong to topic `design`, and the second explicitly says `要求含糊`; the query-wide coverage gate still rejects it. The selector permits two records per topic, but it does not actually perform complementary topic expansion. After one strong match identifies a topic, admitting at most one non-duplicate sibling by salience would satisfy the intended “up to two complementary items” behavior. That improves detail recall but can inject an irrelevant sibling when a topic groups several independent events.

The nominally successful `你有没有养猫` probe reveals a precision bug. Its tokens are only `你有` and `没有`; the single-character entity `猫` is discarded. `cat`, `design`, and `ocean-film` are all selected because their texts contain forms of “没有”. The expected hit is accidental, accompanied by two false positives. Cross-segment CJK grams would recover `养猫`; common polar/question terms such as `没有` should be stop-listed or strongly downweighted. Removing them can hurt retrieval of genuine negative facts, so negative state should remain searchable when paired with a content entity rather than acting as the entity itself.

## Continuous-run failures

`switch-book` has positive query tokens `散文 / 什么 / 有意思`, while `reading` has exact keyword `散文`; nevertheless `rankedCount` is 0. The same query-coverage bug that loses `云南` rejects `散文`. The clause splitter correctly keeps the negative diving clause out of the positive query, so this failure is not an unavoidable multi-clause limitation.

`recall-drink` contains the literal memory terms `平时` and `饮料`, yet has `rankedCount: 0`. `updated-drink` contains exact keyword `咖啡`, but also has `rankedCount: 0`. Because observation uses the same strict `supported` gate as retrieval, the update is stored as a generic utterance rather than reliably linked to topic `drink`. At day 40, `latest-preference` again contains `咖啡` and retrieves neither the old preference nor the dated update. A generic repair needs two parts: allow distinctive exact-term candidacy, and use a slightly different observation rule for explicit correction/update turns so the raw turn can inherit an already known topic. The latest raw assertion should rank above the older one while both remain available as evidence. This increases the risk of attaching a correction to the wrong topic when a turn mentions several entities, so topic inheritance should require one unambiguous strong match or retain multiple candidate links with confidence.

`travel-food` loses `丽江` because the segmenter again emits the place as individual characters in context. Its remaining `吃到 / 喜欢` tokens do not exactly match `吃了一份 / 印象更深`, so `rankedCount` is 0. Recovering `丽江` through cross-segment bigrams or exact metadata scanning is a generic tokenizer repair; no special food rule is needed to make the record a candidate.

The clause splitter handles Chinese comma and full stop but not Chinese/ASCII question and exclamation marks. This matters for `return-state` and `old-recall`, each of which contains two questions. Evidence from both questions is pooled into one coverage denominator, making already strict gating worse. Split on `？！?!` as well, rank each clause separately, and merge candidates. Clause-wise retrieval improves multi-intent recall, but ranking each short clause independently may admit more records; the item and topic caps remain useful controls.

`return-state` selects only `observed-user-21`, the earlier raw question “你买明信片了吗？”, rather than `lijiang-detail` or `lijiang-return`. The selected raw question is not evidence of whether the postcard was sent. Raw user utterances currently receive no assertion/answer-value penalty, and their short token set makes the duplicate filter treat richer records as duplicates after the raw question wins. A generic repair is to keep raw turns for chronology while downranking `asserted:false` questions as answer evidence; question records can support conversational continuity without displacing factual `life`, `source`, or asserted-user records. This improves precision, with the cost that a prior question may sometimes be the only useful conversational cue.

The proactive day-1 response actually uses the `reading` detail “晾衣服”, but all five selected memories are assessed `used:false`. The conservative exposure rule requires at least two word hits or three CJK bigrams; the distinctive three-character term produces one word hit and two bigrams, just below both thresholds. As a result, no exposure and no assistant-supported focus are recorded. The next turn, `嗯，接着说，我想听听你自己的感受`, has empty `recentFocus` and selects nothing. The exact `PRONOUN_ONLY` pattern also rejects a longer utterance containing “接着说”. A generic repair is to accept one distinctive exact keyword/phrase as supported use, and detect discourse continuation markers inside a short utterance rather than requiring the whole normalized string to equal `接着说`. Both changes can falsely carry focus from a passing mention, so focus should remain short-lived and use only the highest-confidence actually used topic.

## What already behaved as intended

The negative controls both return empty. Future memories remain excluded from selection, old directly relevant records can be recalled, duplicate text is suppressed, and the proactive long-horizon experiment shows that exposure accounting has real value when it is recorded: at half-life 7, five seeds produce 48–50 consecutive repeats without exposure, versus 4–5 with exposure, while unique delivered details rise from 8 to 13. This supports repairing exposure detection rather than removing it.

The day-45 proactive turn returns empty, which is appropriate for the aged pool. The core salience decay, burst cap, no assistant self-reinforcement, seeded near-top choice, and whole-record character budgeting are not implicated by the observed recall failures.

## Minimal repair order

1. Fix Chinese entity preservation by adding cross-segment CJK bigrams or exact normalized metadata-term scanning.
2. Replace the 50%-of-all-query gate with tiered evidence: exact distinctive metadata term, high-IDF exact body term, or broad multi-term coverage. Downweight question/function terms.
3. Split all sentence-final punctuation and merge per-clause candidates; retain scoped negative gates.
4. Downrank non-asserted raw questions and prevent them from duplicate-filtering richer factual records.
5. Let one distinctive exact phrase count as delivered use, and broaden short continuation-marker detection.
6. Add optional, audited synonym expansion only for the remaining true paraphrase misses. Keep those rules visible and test their false-positive pairs.

This order addresses demonstrated implementation bugs before adding semantic machinery. It should recover `丽江`, `云南`, `散文`, `咖啡`, and `照片` cases while keeping the two honest semantic misses visible for separate evaluation.
